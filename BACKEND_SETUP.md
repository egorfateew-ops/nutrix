# Подключение общей базы NUTRIX

Сайт остаётся на GitHub Pages. Supabase хранит аккаунты, профили, планы и общие списки покупок.

## 1. Создать проект Supabase
1. Открой https://supabase.com/dashboard и создай проект.
2. Запомни пароль базы данных — он нужен для администрирования проекта, но не вставляется в сайт.
3. Дождись окончания создания проекта.

## 2. Создать таблицы и правила доступа
1. В Supabase открой SQL Editor.
2. Создай новый запрос.
3. Открой файл supabase/schema.sql в этом репозитории, скопируй его полностью в SQL Editor и нажми Run.
4. В разделе Authentication → Providers оставь включённым Email.

В таблице meal_plans хранятся приватные данные профиля. Другие участники не получают к ним прямого доступа. Они могут работать только с общим списком покупок.

## 3. Развернуть функции защищённого обмена
Нужен Node.js и Supabase CLI. В терминале в папке репозитория выполни:

~~~bash
npm install -g supabase
supabase login
supabase link --project-ref YOUR_PROJECT_REF
supabase functions deploy get-shared-plan
supabase functions deploy join-shared-plan
~~~

YOUR_PROJECT_REF — идентификатор проекта из его URL в Supabase Dashboard. Файл supabase/config.toml уже задаёт публичный режим только для чтения общей ссылки. Присоединение к общему рациону требует действующей авторизации.

Edge Functions используют серверные переменные Supabase, в том числе SUPABASE_SECRET_KEYS и SUPABASE_PUBLISHABLE_KEYS. Секретный ключ не добавляй в GitHub и не вставляй в браузер.

## 4. Включить адрес сайта для подтверждения почты
В Supabase открой Authentication → URL Configuration:
- Site URL: https://egorfateew-ops.github.io/nutrix/
- Добавь этот же адрес в Redirect URLs.

Если подтверждение Email включено, после регистрации открой письмо и подтверди адрес.

## 5. Подключить сайт
1. Открой https://egorfateew-ops.github.io/nutrix/.
2. Нажми Облако.
3. Вставь Project URL и Publishable key из настроек API проекта Supabase.
4. Сохрани подключение.
5. Зарегистрируй аккаунт.

В браузере используется только Publishable key (обычно начинается с sb_publishable_). Никогда не вставляй в сайт Secret key (sb_secret_), service_role или пароль базы данных.

## 6. Проверка
- Зарегистрируй два разных аккаунта.
- На первом создай рацион и нажми «Создать ссылку».
- Открой ссылку во втором аккаунте и нажми «Присоединиться».
- Отметь продукт в общем списке. Изменение должно появиться у второго участника через Realtime.

## Важно
- Профили и история рационов приватны для владельца.
- Участник по приглашению видит опубликованный рацион и может изменять только совместный список покупок.
- Отозвать доступ можно отключением общей ссылки и удалением участника из plan_members в Table Editor.
- Цены продуктов — ориентировочные, не официальный каталог магазинов.
