# Подключение общей базы NUTRIX

Сайт остаётся на GitHub Pages. Supabase хранит аккаунты, профили, планы и общие списки покупок.

## 1. Создать проект Supabase
1. Открой https://supabase.com/dashboard и создай проект.
2. Запомни пароль базы данных — он нужен для администрирования проекта, но не вставляется в сайт.
3. Дождись окончания создания проекта.

## 2. Создать таблицы и правила доступа
1. В Supabase открой SQL Editor.
2. Создай новый запрос.
3. Открой файл supabase/schema.sql в этом репозитории, скопируй его полностью в SQL Editor и нажми Run.
4. В разделе Authentication → Providers оставь включённым Email.

Если проект Supabase уже был создан раньше и ты запускал старую версию schema.sql, дополнительно открой файл `supabase/migrations/20261123_training_plans.sql`, скопируй его полностью в SQL Editor и нажми Run. Эта миграция создаёт отдельную таблицу личных тренировочных планов с RLS-политиками. Для нового проекта таблица уже включена в актуальный `supabase/schema.sql`.

В таблице meal_plans хранятся приватные данные профиля. Другие участники не получают к ним прямого доступа. Они могут работать только с общим списком покупок.

## 3. Личный режим без совместных рационов
Приложение работает с личными аккаунтами. Приглашения и общий список покупок не используются. Edge Functions для личных профилей, рационов и дневника замеров не нужны; если ты уже развернул старые функции обмена, их можно оставить — сайт их не вызывает.

## 4. Включить адрес сайта для подтверждения почты
В Supabase открой Authentication → URL Configuration:
- Site URL: https://egorfateew-ops.github.io/nutrix/
- Добавь этот же адрес в Redirect URLs.

Если подтверждение Email включено, после регистрации открой письмо и подтверди адрес.

## 5. Подключить сайт
1. Открой https://egorfateew-ops.github.io/nutrix/.
2. Нажми Облако.
3. Вставь Project URL и Publishable key из настроек API проекта Supabase.
4. Сохрани подключение.
5. Чтобы все посетители сайта подключались автоматически, впиши те же Project URL и Publishable key в файл `cloud-config.js` и отправь коммит в GitHub. Это публичный ключ, он рассчитан на использование в браузере при включённых RLS-политиках.
6. Зарегистрируй аккаунт.

В браузере используется только Publishable key (обычно начинается с sb_publishable_). Никогда не вставляй в сайт Secret key (sb_secret_), service_role или пароль базы данных.

## 6. Личная проверка
- Зарегистрируй свой аккаунт и сохрани профиль.
- Составь рацион: он появится в личной истории.
- Добавь замер веса в разделе «Мой прогресс».
- Составь домашний план в разделе «Тренировки» и сохрани его. После входа на другом устройстве он должен загрузиться из личного аккаунта.
- Открой сайт на другом устройстве, войди в тот же аккаунт и проверь, что профиль, рационы и замеры загрузились.
- При регистрации другого человека его данные должны оставаться отдельными и не пересекаться с твоими.

## Важно
- Профили и история рационов приватны для владельца.
- Каждый аккаунт видит только собственный профиль, историю рационов, покупки и замеры.
- Общие приглашения и совместный доступ в текущем интерфейсе отключены.
- Цены продуктов — ориентировочные, не официальный каталог магазинов.
